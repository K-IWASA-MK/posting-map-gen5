# District Data Transition Rule (次地区展開データ取り扱い規則)

本規則は、既存の地区リポジトリ（複製元地区: source district）を複製して新規地区（target district）の完全独立アプリを構築する際、`data/` 配下の各ファイルをどのように安全に取り扱うべきかを定めた基本就業規則（AGENTS.md）の具現化特化ルールである。

---

## 1. 適用条件と現行地区保護（Scope & Protection）

1. **コピー時限定適用**:
   - 本ルールは、既存地区リポジトリを複製して新地区を構築する「地区初期展開作業」の際にのみ適用される。
2. **現行地区データの完全保護（非破壊原則）**:
   - 本ルールの制定や日常運用によって、現行稼働地区（current district）の `data/` 内の確定データを空にしたり、テンプレート化したり、削除してはならない。現行地区は常にその地区の完成実データで稼働する。

---

## 2. マスター3点セットの同時交換規則（Master Triad Replacement）

以下の3ファイルは「完全地区固有データ」であり、コピー元地区のデータが1文字でも残存してはならない。

| 対象ファイル | 役割 | 新地区展開時の取り扱い |
| :--- | :--- | :--- |
| **`data/address_master.csv`** | 住所マスター (SSOT) | 新地区の確定全小地域データ（1..N）へ丸ごと差し替える |
| **`data/boundaries.geojson`** | 境界ポリゴンデータ | 新地区の確定境界GeoJSON（Features: N）へ丸ごと差し替える |
| **`data/municipality_master.csv`** | 自治体マスター | 新地区の構成自治体一覧・町数へ丸ごと差し替える |

### 遵守事項
- **同時一括交換の義務**: 上記3ファイルは「点（address）・面（boundaries）・枠（municipality）」の不可分な3点セットである。必ず3点同時に新地区の確定データへ一括交換しなければならない。一部のみの先行差し替えや旧地区データの混在は絶対禁止とする。

---

## 3. area_mapping.json の初期化規則（Area Mapping Initialization）

- **対象ファイル**: `data/area_mapping.json`
- **役割**: 旧マスターから新小地域マスターへの実績ステータス継承メタデータ。
- **規則**:
  1. **新規地区での初期化**:
     - 新規立ち上げ地区（過去の旧実績が存在しない地区）では、誤ったステータス継承・データ汚染を防止するため、**必ず空配列 `[]` に初期化**する。
     - コピー元のマッピングデータをそのまま残存させることは重大事故（別地区エリアの誤爆完了扱い）に直結するため絶対禁止とする。
  2. **実績移行地区での例外**:
     - 過去バージョン等からの旧実績データを新小地域マスターへ引き継ぐ必要がある地区に限り、その地区専用の新旧対応表を新規生成して配置する。

---

## 4. 保管場所候補マスターの導出・配備規則（Storage Locations Protocol）

- **対象ファイル**: `data/storage_locations.json`
- **役割**: Hアプリ「保有チラシ」における保管場所候補ドロップダウンの選択肢マスター。
- **生成思想（機械的導出の原則）**:
  - 前地区からのデータ流用、推測、静的コピーを永久に禁止する。
  - 市町村リストを静的な答えとして与えるのではなく、**「選挙開催地（対象自治体）」を入力条件として、公式な衆議院小選挙区画定データから機械的に導出**しなければならない。
  - 「前の地区ではこうだったからコピー」という属人的・非決定論的プロセスを完全に排除する。
- **正式プロトコル手順**:
  1. **選挙開催地（対象自治体）の特定**: 今回のポスティング対象となる基礎自治体を特定する。
  2. **公式小選挙区の特定**: 総務省または各都道府県選挙管理委員会の公定資料を根拠とし、開催地が属する「都道府県・第○区」を特定する（推測禁止）。
  3. **構成市町村一覧の取得**: 当該小選挙区を構成する全自治体（活動拠点・保管拠点候補）を取得する。
  4. **地区 data/ への配備**: 取得した市町村一覧を配列形式（JSON）で `data/storage_locations.json` に配置する。
- **遵守事項**:
  - **Universal Engine非侵襲**: `active/` 側の実行エンジンコード内に自治体名を一切ハードコードしてはならない。
  - **他地区データの完全遮断**: 過去の他地区リポジトリの `storage_locations.json` を参照・流用することを絶対禁止とする。

---

## 5. 一次原本の持ち込み絶対禁止（Raw Data Exclusion）

以下のフォルダーおよびファイル群はコピー元地区固有の一次原本（原本エビデンス）であり、新地区リポジトリへ持ち込んではならない。

- **持ち込み禁止対象**:
  - `data/raw/`（デジタル庁原本CSV、原本ZIP、抽出監査ログ等）
  - `data/raw_estat_r2/`（e-Stat 令和2年国勢調査小地域境界 Shapefile バイナリ群）

### 遵守事項
- **リポジトリ汚染の遮断**: コピー元地区の Shapefile や巨大な ZIP ファイルを新地区リポジトリの Git 履歴に混入させてはならない（AGENTS.md 第0条・第4条厳守）。
- **新地区原本の取得**: 新地区のマスター生成や境界検証に必要な一次原本は、新地区用に新しく取得して配置・検証すること。
- **外部原本の保管統制**: 新地区用の外部原本の取得・保管（地区専用Google Driveでの管理）およびscratch保存禁止ルールについては、[district-external-data-governance-rule.md](district-external-data-governance-rule.md) に従うこと。

## 6. 3点セットの整合性判定ゲート（Master Triad Integrity Gate）

新地区データへの交換完了後、スプレッドシートへのプロビジョニング（RUNBOOK Stage 3）へ進む前に、必ず以下の厳密整合性を機械検証しなければならない。

### 機械検証条件（Rule-01 〜 Rule-04）
1. **総件数 $N$ の完全一致**:
   $$\text{address\_master.csv の有効行数} = \text{boundaries.geojson の Feature数} = \text{municipality\_master.csv の total\_towns 合計} = N$$
2. **rowId（1..N）の完全 1:1 対応**:
   - `address_master.csv` の `rowId`（1..N 連番）と `boundaries.geojson` の `properties.rowId` が欠損・重複なく 1:1 で一致すること。
3. **自治体名の完全一致**:
   - `address_master.csv` に出現するすべての `city_name` が `municipality_master.csv` の `city_name` と完全一致すること。
4. **旧地区残骸ゼロ確認**:
   - 3点セット内に前地区の自治体名、町名、旧コードが 0件 であること（マスターデータ内のテキスト検索・キー照合による静的スキャンおよび不整合ゼロ証跡の記録）。

### 🛑 HARD STOP 条件
上記検証において **1件でも不整合（エラー・警告）が検出された場合、プロビジョニング作業を即座に HARD STOP** する。不整合を放置したまま Google リソースやスプレッドシートへの書き込みを開始することを絶対禁止とする。

---

## 7. 既存コード非侵襲原則（Code Non-Invasive Principle）

- 新地区アプリの成立は「スプレッドシート名の決定」＋「上記規則に従った `data/` の交換」のみによって達成されなければならない。
- データの差し替えに対応するためと称して、`active/` 側のプログラムコード（HTML, JS, GAS）に地区固有の分岐・設定・ハードコードを追加することを絶対禁止とする（AGENTS.md 第4条・第5条厳守）。

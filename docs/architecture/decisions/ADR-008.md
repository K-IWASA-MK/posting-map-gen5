# ADR-008: Gate変更統制とAI Agent Governance (Gate Change Control and AI Agent Governance)

- **Status**: ACCEPTED (ADOPT)
- **Date**: 2026-09-22
- **Deciders**: Universal POSTING MAP Architecture Board
- **Consulted**: `AGENTS.md` §1〜§7, `.agents/rules/agent-authority.md`, `.agents/rules/verification-gates.md`, `docs/api/API_CONTRACT.md` §18

---

## 1. Context (背景と課題)

AI Agent（自律型AIアシスタント）を活用したシステム設計・開発・運用において、AIが自己判断で指定スコープ外のファイルを「ついで」にリファクタリングしたり、SSD上の他地区リポジトリを参照して地域固有コードを混入させたり、MASTER（人間監督者）の明示的承認を経ずに独断でコミット・プッシュ・デプロイを行うリスクが存在する。

過去の知見に基づき、システムの完全性とアーキテクチャの純粋性を担保するためには、厳格なガバナンスモデル（多段階 Gate 統制、最小権限の原則、Human-in-the-Loop、作業前後の差分監査）をアーキテクチャ上の最高位決定として公式に確定する必要がある。

---

## 2. Decision (決定内容)

Universal POSTING MAP では、**Gate 統制および AI Agent ガバナンス原則** を正式採用し、すべての AI 社員および開発作業に適用する。

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. 8-Stage Protocol (変更実行プロトコル)                    │
│    Stage 1: Plan (事前宣言: 対象, 関数・行, 内容, 理由)     │
│    Stage 2: Master Review & Approval (承認なき作業は禁止)    │
│    Stage 3: Implementation (最小侵襲・スコープロック)       │
│    Stage 4: Test & Verify (Gate -1 構文監査, 単体テスト)     │
│    Stage 5: Diff & Audit (事前宣言と実差分の 1行単位照合)    │
│    Stage 6: Commit (承認後の原子コミット)                   │
│    Stage 7: Push & Deploy (承認後の反映)                    │
│    Stage 8: Runtime Verification (本番稼働証跡の採取)       │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. AI Agent ガバナンス絶対原則 (AI Governance Invariants)    │
│    ・Repository Boundary: 他地区リポジトリの参照・検索完全禁止 │
│    ・No Plan ──► No Proceed ──► No Implementation           │
│    ・No Silent Changes (未宣言変更の完全排除)                │
│    ・Scope Lock (指定範囲外への波及・改善の絶対禁止)         │
│    ・Unexpected Condition ──► Report ──► STOP (独断修正禁止) │
│    ・Human-in-the-loop: Commit / Push / Deploy は人間承認制 │
└─────────────────────────────────────────────────────────────┘
```

### 【詳細規程と制約事項】
1. **Repository Boundary (永久原則)**:
   - 現在作業対象としているリポジトリの Git root を作業・探索・検索・読み取り・操作の絶対境界とする。
   - SSD上に存在する他地区（OKAYAMA-02、KUWANA等）のリポジトリやフォルダーを、「参考」「比較」を含め一切参照・探索しない。
2. **最小侵襲とスコープロック (Scope Lock)**:
   - 指定範囲外のコードは不可侵とする。必要最小限の行数のみを変更し、「ついで」の改善、リファクタリング、別箇所への波及は絶対禁止とする。
3. **No Silent Changes と事前宣言**:
   - ファイル変更前に必ず「対象ファイル、対象関数・行、変更内容、変更理由、変更しない範囲」を日本語で事前宣言する。未宣言の変更が1行でも存在した場合は即時 HARD STOP とする。
4. **Human-in-the-loop (承認ゲート)**:
   - プラン承認前の実装着手、テスト未完了でのコミット、承認前のプッシュおよびデプロイは固く禁じる。
5. **現時点の実装実態の境界 (No Phantom Configs)**:
   - 現時点でリポジトリ内に存在しない `hooks.json` や `mcp_config.json` 等を「実装済み・稼働中」として扱わない。
   - 現在は `AGENTS.md` および `.agents/rules/` によるプロンプト・行動規程レベルでの統制が有効であり、フック機構や MCP サーバーによる機械的ブロックは「将来実装（FUTURE IMPLEMENTATION）」として正確に区別する。

---

## 3. Consequences (影響と効果)

### ポジティブな影響
- AI Agent による意図しないコード破壊、スコープ拡大、勝手なコミット・プッシュが完全に抑止される。
- すべての変更が事前宣言と事後照合（`git diff`）によって検証され、極めて高い透明性と説明責任が確保される。
- 他地区のコードやデータの混入が根本から遮断され、Universal Engine の純粋性が保たれる。

### ネガティブな影響 / リスクと緩和策
- **開発速度の制約**: 厳格なプロトコルと人間承認のステップにより、短期的な作業ステップ数は増加するが、手戻りや本番障害・データ破壊のリスクが最小化されるため、中長期的な総合開発生産性は劇的に向上する。

# ADR-010: 1地区自己完結型バックエンドアーキテクチャおよび旧親GAS集中ルーティング廃止決定 (1-District Self-Contained GAS Architecture & Deprecation of Shared Parent GAS)

- **Status**: SUPERSEDED / UPDATED (2026-10-17: 親GAS集中ルーティングを廃止し、当該Spreadsheetに付属する1地区専用GAS方式へ統一)
- **Date**: 2026-10-17 (Original: 2026-09-23)
- **Deciders**: Universal POSTING MAP Architecture Board / MASTER
- **Consulted**: `docs/architecture/SUPREME_PRODUCT_PRINCIPLES.md`, `AGENTS.md`, `docs/architecture/01_DESIGN_CONTRACT.md`, `docs/architecture/CURRENT_ARCHITECTURE.md`

---

## 1. Context (背景と課題)

Universal POSTING MAP は、[docs/architecture/SUPREME_PRODUCT_PRINCIPLES.md](../SUPREME_PRODUCT_PRINCIPLES.md) 第3条および [AGENTS.md](../../../AGENTS.md) 第1条において以下の最高位物理境界を定めている：
```text
1地区 = 1完成アプリ = 1単独フォルダー = 1単独リポジトリ = 1単独ドメイン = 1単独スプレッドシート（DB） = 当該Spreadsheetに付属する1地区専用GAS = 地区専用外部設定
```

過去に検討された「単一親GASによる複数地区共用ルーティング方式」には、以下の重大な構造的リスクが存在した：
1. **障害影響範囲（Blast Radius）の単一障害点化**: 1つの親GASのクォータ枯渇・設定変更・デプロイ障害が全地区の稼働を同時に停止させる。
2. **クロステナント設定結合リスク**: 1つの Script Properties に全地区の接続情報を集約すると、1地区の切り離し・譲渡・閉鎖時に他地区の設定領域へ接触する必要がある。
3. **1地区完全自律閉塞原則との矛盾**: フォルダー・リポジトリ・ドメイン・DBが1地区単独であるにもかかわらず、GASと外部設定のみが中央結合される非対称性が生じる。

---

## 2. Decision (決定内容)

Universal POSTING MAP では、複数地区共用の親GAS集中ルーティング方式を**永久に廃止（DEPRECATED）**し、**「当該Spreadsheetに付属する1地区専用GAS（1-District Self-Contained GAS）」方式** を唯一の正規バックエンドアーキテクチャとして確定する。

```text
                 ┌─────────────────────────────────────────┐
                 │ 1地区単独リポジトリ                     │
                 │ active/ = Universal Engine (全地区同一)  │
                 │ data/   = 当該地区専用マスターデータ    │
                 └────────────────────┬────────────────────┘
                                      │ clasp push (地区専用Script ID)
                                      ▼
                 ┌─────────────────────────────────────────┐
                 │ 当該Spreadsheetに付属する1地区専用GAS   │
                 │ SpreadsheetApp.getActiveSpreadsheet()   │
                 │ (+ TARGET_SPREADSHEET_ID フォールバック)│
                 └────────────────────┬────────────────────┘
                                      │ 1対1 直接結合 + verifyIntegrityGuard
                                      ▼
                 ┌─────────────────────────────────────────┐
                 │ 1地区単独スプレッドシート (DB)          │
                 │ SYSTEM_INFO (地区コード = districtId)   │
                 └─────────────────────────────────────────┘
```

### 【詳細決定事項】

#### 1. 当該Spreadsheetに付属する1地区専用GASの原則
- 各地区は、当該地区の Google Spreadsheet（DB）に1対1で付属する専用の GAS プロジェクトおよび専用 Web App URL を保有する。
- `active/**` のコード自体は **Universal Engine** として全地区で100%同一であり、地区ごとのコード改変・個別分岐は永久に禁止する。

#### 2. 単一地区DB解決と整合性ガード (`SpreadsheetResolver`)
- **第1優先**: `SpreadsheetApp.getActiveSpreadsheet()` により、当該GASが付属するスプレッドシートを直接解決する。
- **第2優先（フォールバック）**: `getActiveSpreadsheet()` が `null` を返す実行コンテキストでは、Script Properties の `TARGET_SPREADSHEET_ID` から `SpreadsheetApp.openById()` で解決する。
- **整合性検証 (`verifyIntegrityGuard`)**:
  - リクエストに `districtId` が指定されている場合、オープンしたスプレッドシートの `SYSTEM_INFO` シート「地区コード」と厳格に照合し、不一致の場合は即座に `DISTRICT_MISMATCH` で遮断する。

#### 3. 認証・認可の厳格維持
- **処理パイプライン**:
  ```text
  Request 受信
      ↓
  SpreadsheetResolver による自地区DBの解決 + verifyIntegrityGuard (DISTRICT_MISMATCH 検証)
      ↓
  LINE Access Token 検証 ➔ 認証済み lineUserId の取得 (Identity Proof)
      ↓
  自地区DB（名簿シート）との突合 ➔ 地区所属・利用資格確認 (Authorization)
      ↓
  認可 PASS / DENY
      ↓
  Spreadsheet 業務操作
  ```
- **クライアント無信頼原則**: クライアント送信の `staffId`, `staffName`, `branchId` は一切信用せず、検証済み `lineUserId` またはサーバー検証済み管理者セッショントークン（`sessionToken`）のみを根拠とする。

---

## 3. Consequences (影響と効果)

### ポジティブな影響
- **完全な地区単位の自律閉塞**: 1地区の開設・運用・保守・閉鎖（Deprovisioning）が他地区に1ミリも影響を与えない。
- **クォータと権限の完全分離**: GAS実行時間・UrlFetchクォータ・Script Properties・Drive証跡フォルダが地区ごとに物理隔離される。
- **フロントエンド契約の不変性**: H-App および Dashboard の公開API契約（17アクションのAction名・入出力形式・エラー意味論・発火順序）は100%同一に保たれる。

---

## 4. Verification (検証要件)

1. **単一地区解決・整合性ガード検証**:
   - `getActiveSpreadsheet()` 優先解決および `TARGET_SPREADSHEET_ID` フォールバックが正常に機能すること。
   - `SYSTEM_INFO` の地区コードと異なる `districtId` が指定された場合、`DISTRICT_MISMATCH` で即座に拒絶されること。
2. **認可境界検証**:
   - 未登録ユーザーの `NOT_REGISTERED` 拒否、無効トークンの `UNAUTHORIZED` 拒否、管理者セッションの地区拘束がすべて維持されること。

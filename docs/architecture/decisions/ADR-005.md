# ADR-005: 確定データSSOT・冪等性・実績保護 (SSOT, Idempotency, and Distribution Record Protection)

- **Status**: ADAPTED (ADAPT)
- **Date**: 2026-09-22
- **Deciders**: Universal POSTING MAP Architecture Board
- **Consulted**: `docs/architecture/01_DESIGN_CONTRACT.md` §2, `docs/data/DATA_DICTIONARY.md` §0, §1, §5, `docs/data/DATA_LIFECYCLE.md` §2, `docs/api/API_CONTRACT.md` §4, §17

---

## 1. Context (背景と課題)

外部のアーキテクチャ提案において、「最新タイムスタンプ勝者（timestamp winner）によって既存レコードを無秩序に上書き更新する」という設計案が提示された。
しかし、この設計はすでに記録された配布完了実績を勝手に上書きしてしまう重大な欠陥を抱えている。

ポスティング業務において、配布実績シートは「1か月・1 rowId = 1行」の月次進捗台帳であり、当月に記録された初回完了実績は不変の客観的事実として保護されなければならない。最新タイムスタンプによる上書き（timestamp winner）を排除し、同一操作の再送は duplicate として遮断し、当月完了済みの町丁目に対する別操作は上書きせず existing record を保護する仕組みが不可欠である。

---

## 2. Decision (決定内容)

Universal POSTING MAP では、**「Spreadsheet DB を唯一の正本 (SSOT: Single Source of Truth)」** と定め、正当な配布実績を絶対に消去・上書きしない以下の冪等性・実績保護モデルを確定する。

```text
┌─────────────────────────────────────────────────────────────┐
│ 識別子の厳格な分離                                          │
│   ・rowId     : 地理マスター識別子 (町丁目を示す番号)        │
│   ・requestId : 1回の配布完了操作を識別する UUID v4         │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ Backend (GAS) での受容判定                                  │
│                                                             │
│ 1. 同一 requestId の再送 (通信瞬断・リトライ・連打)         │
│    ──► Idempotent Hit                                       │
│        新規書き込みをスキップし、既存レコード情報を返却     │
│        (HTTP 200, isDuplicate: true)                       │
│                                                             │
│ 2. 異なる requestId の送信                                   │
│    ──► 当月未完了 rowId であれば初回完了として保存          │
│        同一 rowId で当月完了済みの場合は上書きせず          │
│        Already Completed として既存実績を保護 (DB書込0)      │
└─────────────────────────────────────────────────────────────┘
```

### 【絶対不変条件と禁止事項】
1. **Spreadsheet DB の SSOT 性**:
   - 正本データは Google Spreadsheet DB にのみ存在し、端末ローカルの IndexedDB はオフライン送信用キューおよび読み取りキャッシュに過ぎない。
2. **月内1エリア1行固定と既存実績の保護**:
   - 配布実績シートは「1か月・1 rowId = 1行」として管理し、当月の初回完了のみを永続化する。
   - 同一 `rowId` が当月完了済みである場合、異なる `requestId` であっても上書き・新規追記せず `alreadyCompleted: true` として既存実績を保護する（同月再配布なし、翌月に新しい月次シートで未配布から新しく開始する）。
3. **Timestamp Winner (上書きルール) の採用禁止 (REJECT)**:
   - タイムスタンプ比較によって既存の完了実績行を無秩序に上書き・更新する方式は完全に禁止する。
4. **Server Wins の厳格な境界**:
   - 「Server Wins」とは、クライアントの一時的な画面表示状態やオフラインキャッシュとサーバー（Spreadsheet DB）の間でデータ不整合が生じた際、サーバー側に永続化された確定データを正本として優先する原則（API_CONTRACT §17）であり、サーバーが既存実績を上書き消去することを意味しない。
5. **PinStatus と DistributionRecord の分離**:
   - `PinStatus`（現在進行中のピン色・状態）は最新の完了状態を反映して更新（Update）されるが、`DistributionRecord`（月次完了実績台帳）は当月1 rowId = 1行の確定実績台帳である。この 2 つのデータ構造を混同してはならない。

---

## 3. Consequences (影響と効果)

### ポジティブな影響
- 当月に記録された初回完了実績が確実に保護され、後勝ちタイムスタンプ等による無秩序な上書きが完全に防止される。
- 通信エラーやリトライに伴う多重計上は `requestId` による厳密な冪等性判定（duplicate）によって防止される。
- 翌月には新しい月次シート（`配布実績YYYY-MM`）が作成され、全町丁目が「未配布」からクリーンに再開できる。

### ネガティブな影響 / リスクと緩和策
- **月次管理モデルの徹底**: 同月内の再配布は行わず初回完了をもって当月ロックとなるため、翌月新月シートによる新周期開始運用を徹底する。

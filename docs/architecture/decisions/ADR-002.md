# ADR-002: 自由配布・非事前割当モデル (Autonomous Free Posting Model)

- **Status**: ACCEPTED (ADOPT)
- **Date**: 2026-09-22
- **Deciders**: Universal POSTING MAP Architecture Board
- **Consulted**: `AGENTS.md` §1, §2, `docs/data/DATA_DICTIONARY.md` §0, §5, `docs/data/DATA_LIFECYCLE.md` §2, `docs/api/API_CONTRACT.md` §7

---

## 1. Context (背景と課題)

従来のポスティング業務や管理システムでは、しばしば「個人への担当エリアの事前割り当て」「目標枚数（ノルマ）の設定」「活動可能地域の制限」「出勤・参加管理」といった管理統制型のデータモデルが導入されがちであった。
しかし、POSTING MAP が支援する活動の本質は、党員・ボランティアが自身の都合や生活圏に合わせて自律的にポスティングを行う「自由な活動」である。
管理・割当モデルを導入した場合、活動の心理的ハードルが高まり、自律的な参加が著しく阻害される。

---

## 2. Decision (決定内容)

Universal POSTING MAP では、**「ポスティングは完全に自由」** をシステムの最高位業務不変条件として定め、以下のデータモデルと運用原則を確定する。

```text
Person (党員個人)
   ├── 組織所属 ──► Branch (所属支部: 組織上の所属先)
   │
   │ 1. performs (完全に自由なポスティング活動: 活動場所制限・担当エリアなし)
   ▼
DistributionRecord (配布実績事実)
   ├── rowId (町丁目行番号)
   ├── cityName / townName (どこで)
   ├── completedAt (いつ)
   ├── count (何枚)
   ├── staffId / staffName (誰が: Backend強制解決)
   ├── gps (latitude, longitude, accuracy: 空間証跡)
   └── photo (photoFileId, photoUrl: 物理証跡)
```

### 【絶対不変条件 (Non-Negotiable Invariants)】
1. **個人担当エリアの不存在**:
   - `Person → AssignedArea` は存在しない。システムにいかなる担当割当フィールドも設けない。
2. **活動可能地域割当の不存在**:
   - `Person → ActivityArea` は存在しない。個人に対して活動地域を限定・許可するモデルを排除する。
3. **支部による活動場所制限の不存在**:
   - `Branch → AllowedActivityRegion → Person` という制約モデルを作らない。「支部の活動対象地域」は組織上の管轄・観測地域であり、「党員のポスティング可能範囲」ではない。「所属支部」と「ポスティングした場所」は完全に独立した別概念である。
4. **個人ノルマ・強制参加の不存在**:
   - `Person → Quota`、出勤管理、ペナルティ機能は一切存在しない。
5. **発生した客観的事実の記録**:
   - 配布実績（`DistributionRecord`）は、「誰が・いつ・どこで・何枚配ったか」という発生した客観的事実のみを記録する。
6. **現在状態と完了事実の厳格な分離**:
   - `PinStatus`（現在リアルタイムに誰が作業中か）は「一時的な現在状態」であり、活動員同士が視覚的に重複を避けるための緩やかな協調表示に過ぎない。
   - `DistributionRecord`（完了した活動実績）は「永続化される確定事実」であり、この2つのライフサイクルおよび責務を絶対に混同してはならない。

---

## 3. Consequences (影響と効果)

### ポジティブな影響
- 配布員は支部やエリアの境界に縛られず、完全に自由かつ自律的にポスティング活動を行うことができる。
- 管理者による事前割り当て作業やノルマ管理のオーバーヘッドが完全に消滅する。
- データの構造が「発生した事実の記録」に純化され、シンプルで堅牢なデータモデルが維持される。

### ネガティブな影響・トレードオフ
- 「誰がどこを配るか」をトップダウンで計画・強制管理することはシステム上不可能となる（システムの基本思想として許容）。

# ADR-001: 4層物理分離アーキテクチャ (4-Tier Physical Separation)

- **Status**: ACCEPTED (ADOPT)
- **Date**: 2026-09-22
- **Deciders**: Universal POSTING MAP Architecture Board
- **Consulted**: `docs/architecture/01_DESIGN_CONTRACT.md` §2, `docs/data/DATA_LIFECYCLE.md` §1, `docs/api/API_CONTRACT.md` §2

---

## 1. Context (背景と課題)

POSTING MAP の初期開発および旧地区運用において、スプレッドシート内に Apps Script が直接埋め込まれたコンテナバインドスクリプトや、シート編集イベントに依存したトリガー駆動型の自動計算が存在していた。
これにより、以下の深刻な問題が発生した：
1. スプレッドシートのコピーや破損に伴うスクリプト消失・バージョン乖離。
2. 業務ロジック、UI、データベース、マスターデータが混在し、変更影響範囲の局所化が不可能。
3. 地区展開時にコードとデータが癒着し、Universal エンジンとしての全国展開が阻害される。

---

## 2. Decision (決定内容)

Universal POSTING MAP では、以下の **4層物理分離アーキテクチャ** を正式採用し、恒久的な設計契約として確定する。

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. Client Tier (フロントエンド層)                            │
│    ・Hアプリ (現場活動アプリ: PWA / 静的ホスティング)       │
│    ・Dashboard (統括観測アプリ: 静的ホスティング)           │
│    ・GitHub Pages 等の静的 CDN から配信                     │
└──────────────────────────────┬──────────────────────────────┘
                               │ HTTPS POST/GET (JSON API)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. Backend Tier (業務ロジック・API層)                       │
│    ・Standalone Google Apps Script (GAS) API (`v2_api.js`)   │
│    ・認証・Identity解決・入力値検証・排他制御・証跡保存     │
└──────────────────────────────┬──────────────────────────────┘
                               │ Lock下での安全なデータ読み書き
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. Database Tier (永続化層: Pure DB)                        │
│    ・Google Spreadsheet (Pure DB: スクリプト内包ゼロ)       │
│    ・Google Drive (写真・証跡バイナリ保管)                  │
│    ・コンテナバインド・シート内トリガー・マクロは完全禁止   │
└─────────────────────────────────────────────────────────────┘
                               ▲
                               │ 地区展開時・Gate時に参照
┌──────────────────────────────┴──────────────────────────────┐
│ 4. Master Data Tier (マスターデータ層)                      │
│    ・Git 管理マスターデータ (`data/` 配下)                   │
│    ・`address_master.csv`, `boundaries.geojson`, `config.js`│
│    ・地域差を吸収する純粋な静的定義                         │
└─────────────────────────────────────────────────────────────┘
```

### 厳格な制約事項
1. **Spreadsheet = Pure DB の徹底**:
   - スプレッドシートはリレーショナルテーブル同等の純粋なストレージとして扱い、いかなるスクリプト、カスタム関数、`onEdit` トリガーも含めてはならない。
2. **GAS = Standalone のみ**:
   - すべてのサーバーサイドロジックは独立した Standalone GAS プロジェクトとして構築・デプロイし、シートから物理的に分離する。
3. **Master Data の位置付け**:
   - 行政区画、町丁目、境界座標等の地域差は、Git リポジトリ内の `data/` 層に集約し、コード層（`active/`）に地域固有のハードコードを含めない。

---

## 3. Consequences (影響と効果)

### ポジティブな影響
- コードとデータが完全に分離され、スプレッドシートのバックアップ・復元時にプログラムが破壊されるリスクがゼロになる。
- フロントエンド・バックエンド・データベースの各層を独立してバージョン管理・監査できる。
- 全国各地区への展開時、`active/` のコードを変更せず、`data/` の差し替えのみで対応可能となる。

### ネガティブな影響・トレードオフ
- スプレッドシート側の数式やトリガーによる自動集計が禁止されるため、すべての整合性チェックと集計ロジックを Standalone GAS 側で実装する必要がある（`MonthlySheetResolver` や集計サービスの責務増大）。
